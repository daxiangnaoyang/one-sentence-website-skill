# 脱敏案例：一个人如何把 AI 共学品牌做成可持续迭代的官网

> 这是准备放入 `one-sentence-website` Skill 的案例素材，不是对外发布稿。公开前需要用户审核事实、措辞和是否保留本案例。

## 一句话需求

一个由个人运营的 AI 共学品牌，需要一个让陌生访客快速判断“这是什么、适不适合我、下一步从哪里开始”的官网；网站还要能持续承载课程地图、内容入口、企业服务说明、品牌区分信息和搜索引擎可读结构。

## 起点与约束

- 站点选择静态 HTML/CSS/JavaScript，保留低依赖和可迁移性。
- 第一版先解决定位、入口和内容结构，再逐步增加视觉和交互；没有先上复杂框架或后台系统。
- 课程、服务、报名和联系入口必须区分“页面说明”与“实际交付”，不使用虚构评价、虚构结果或假提交成功。
- 发布前要能检查 canonical、Open Graph、JSON-LD、robots、sitemap、移动布局和页面链接。

## 实际迭代链

### 1. 从品牌落地页开始

先建立单页站点、品牌说明、课程/学习入口、公开联系入口和基础资源。站点同时配置 GitHub Pages 发布工作流，让每次主分支更新都有可重复的发布路径。此阶段目标是先让访客看懂入口，不追求一次完成所有功能。

### 2. 按访客判断重排内容

后续迭代把页面改成“先判断，再选择路线”的结构：首屏说明品牌服务谁；课程页解释学习地图；关于页说明公开身份和方法；AI 现场页承载持续内容；企业页单独说明岗位任务试点。导航和 CTA 围绕访客下一步组织，而不是围绕内部文件夹组织。

### 3. 先做可用的视觉系统，再加动效

视觉从暖色、手绘感、卡片和留白开始，随后补充响应式布局、轻量 CSS 动画和可降级的 JavaScript 交互。动效服务于“看懂页面层级”，不把首页做成必须依赖动画才能阅读的展示页。移动端和减少动效偏好需要保留可读路径。

### 4. 把搜索可读性当作页面结构

在页面内容稳定后，补充 canonical、Open Graph、JSON-LD、`robots.txt`、`sitemap.xml`、`llms.txt` 和搜索引擎提交文件。JSON-LD 描述的是页面中已经公开的身份、组织、课程和网站关系；它不是用来填充没有证据的资格、数据或结果。

### 5. 增加品牌区分页

当品牌名称可能与其他实体混淆时，单独建立品牌区分页：明确自身定位、适合与不适合的人、与相似名称实体的边界、公开入口和相关说明文章。这个页面同时被首页 FAQ、`llms.txt`、站点地图和外部文章回链，形成可检查的内部信息结构。

### 6. 迁移到自定义域名

域名迁移不是只替换一个首页链接。需要同步页面 canonical、OG URL、JSON-LD、`llms.txt`、robots、sitemap、品牌区分页和相关外部入口，再分别检查非规范主机是否重定向、规范主机是否返回页面。案例公开版只写“从临时站点迁移到自定义域名”，不公开真实域名和注册商信息。

### 7. 在结构稳定后增加 3D 视觉锚点

最后才增加本地 3D 资源、JavaScript 视差和视觉锚点。模型和脚本属于可替换资产，加载失败时保留静态降级；鼠标互动是增强层，不改变页面内容、导航和联系入口。这个顺序降低了“先做炫技，后补定位”的返工成本。

## 可复用的实施流程

```text
一句话定位
  → 访客与入口访谈
  → 静态模板与内容事实
  → 本地页面迭代
  → 响应式与可访问性检查
  → SEO/GEO 结构检查
  → GitHub Pages 或托管平台预览
  → 自定义域名与 DNS/TLS 验收
  → 继续内容和视觉迭代
```

每个阶段都有可回滚的提交；新增视觉资产不覆盖旧资源，域名迁移不删除旧入口，平台上线状态和本地源码状态分开记录。

## 验收清单

- [ ] 首页能在一句话内说明服务对象和下一步入口。
- [ ] 课程、内容、关于、企业服务和品牌区分页之间的链接可用。
- [ ] 移动端没有横向溢出，键盘和减少动效用户仍能阅读核心内容。
- [ ] canonical、OG、JSON-LD、robots、sitemap 和 `llms.txt` 指向同一规范站点。
- [ ] JSON-LD 只描述页面已有事实，未把页面文案当作独立资格证明。
- [ ] 联系入口是真实链接或明确的下一步，不伪造表单成功。
- [ ] 域名、DNS、TLS、平台部署和内容验收分别有证据。
- [x] 对外案例已删除账户、内部 commit、个人联系资料和未授权图片；域名与首屏截图为用户明确授权公开内容。

## 这个案例教会 Skill 什么

1. “一键部署”应当是一个可续接的状态机，不是一次性把源码上传出去。
2. 个人网站的主要工作不是选模板，而是把定位、内容、入口、搜索结构和持续更新连接起来。
3. 域名迁移是跨文件、跨平台的引用同步问题，必须列清清单后再改。
4. 先交付静态可读版本，再增加动效和 3D 资源，能让失败可回滚、体验可降级。
5. 页面、搜索结构和真实交付证据必须分开；文案不能自动升级为事实证明。

## 脱敏边界

发布版本不得出现：真实仓库地址、个人实名、邮箱、微信/公众号二维码、社交账号、证书机构名称、内部路径、commit hash、账单、域名注册商、DNS 记录和未公开经营数据。经用户明确授权的真实域名与首屏截图除外。

## 来源与证据边界（审核版）

- 本素材依据本地官网仓库的可读提交历史和页面源码整理。
- “经过多轮迭代”和文件变更属于仓库事实；“降低返工成本”“形成可检查结构”是基于这些事实的工作流推断。
- 本素材没有声称访问量、转化率、搜索排名、商业收入或课程交付结果。
- 真实公网部署、域名购买、DNS/TLS 和最终用户验收需在公开版中继续标记为“已验证/未验证”，不能由本地源码推断。
