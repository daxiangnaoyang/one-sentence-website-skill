# 分轮访谈与一句话路由

这份 Skill 的入口可以只有一句话，例如“我想要一个能让客户找到我的网站”。这句话足以启动工作，但不足以生成可信页面。Agent 应把信息收集拆成可暂停的小轮次：每轮只问会阻塞下一步的 1–3 项，收到答案就写入当前项目的非敏感状态，再继续执行不依赖答案的工作。

## 首轮：判断边界

先复述一句可验收目标：

> 你要的是一个用于【个人介绍/作品展示/个体服务/内容发布】的网站，面向【受众】，希望先在【平台或未决定】上线；我会先生成本地可预览版本，再在账户和发布授权齐备后上线。

只问：网站类型；主要访客和希望访客完成的动作；是否已有域名、托管账户或材料；是否商业使用以及是否需要收款、会员、CMS 或表单。不要在首轮索要密码、验证码、银行卡、身份证照片或全部社交账号。没有答案的字段写 `未获取`，不猜测。

## 第二轮：模板与内容

| 目标 | 模板 | 最小页面内容 |
| --- | --- | --- |
| 个人介绍 | `profile` | 名称、身份、简介、所在地或远程方式、行动入口 |
| 作品展示 | `portfolio` | 真实作品、每项事实摘要、链接或未公开状态 |
| 服务介绍 | `service` | 服务对象、范围、合作步骤、咨询入口、不可承诺事项 |
| 内容主页 | `creator` | 主题定位、精选内容、栏目、外部平台链接 |

第二轮只问缺口：名称和身份如何公开、可发布的事实、头像/图片是否有发布权、公开联系方式。没有作品链接时可用“摘要 + 未公开”做本地草稿，但生产检查前必须替换或删除演示内容。

## 第三轮：平台与商业属性

- 纯静态、少量更新、个人非商业：可考虑 Vercel Hobby 或 Cloudflare。
- 商业用途：先核对 Vercel 账户计划和条款，不把 Hobby 当作默认商业方案。
- 需要 Git 自动构建：Cloudflare Pages 创建时选 Git 集成；Direct Upload 项目不能原地转 Git，需要新项目迁移。
- 需要 Worker 逻辑或边缘 API：选 Cloudflare Workers Static Assets。
- 只有需要常驻进程、专用软件、数据库或用户明确要求独立服务器时才走 VPS。

推荐平台时同时比较开户、费用、域名续费、DNS/TLS、备份、迁移和退出成本，不只比较首次上线速度。

## 登录与采购检查点

使用官方 OAuth、官方 CLI 登录或浏览器控制台。用户在官方页面输入密码、验证码、付款信息和身份资料；Agent 只记录非敏感账户、组织/项目 ID、授权范围和证据 URL。域名购买前记录精确域名、注册年限、币种、首次价格、续费价格和自动续费状态。价格、库存或订单状态不明确时先查订单，不重复付款。

## 可复制对话

用户：“我是一名独立摄影师，想要一个网站接商业拍摄。”

Agent：“我先按作品集网站处理。请补充三项：面向哪类客户？准备公开的作品各叫什么？客户通过邮件、电话还是已有表单联系你？你已有域名或 Vercel/Cloudflare 账户吗？”

用户：“没有域名，主要接品牌和活动拍摄，先放邮箱。”

Agent：“已记录 `portfolio`、受众为品牌和活动客户、行动入口为邮件。我会先生成本地演示；域名购买会展示精确价格、续费和自动续费状态，等确认后继续。”

用户中途回来时，先读取 `.site-state.json` 和实际文件，再检查远端项目、部署和 DNS；域名已购买就继续 DNS，不重新购买；登录过期只请求重新登录。

## 停止条件

缺少目标、无法确认内容真实性、商业条款不明、未授权采购/支付/发布、账户过期或远端冲突时，状态写 `WAITING_USER` 或 `BLOCKED`，说明最小缺口。不要用默认姓名、虚构客户、假案例或“已上线”填空。
