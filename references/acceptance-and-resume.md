# 验收、状态与续接

构建、部署、域名和内容验收是四个不同门。每个门都记录证据，不用一个“成功”覆盖全部状态。

## 状态契约

建议的 `.site-state.json`（仅本地非敏感状态，可加入 `.gitignore`）：

```json
{
  "schema": 1,
  "status": "LOCAL_VERIFIED",
  "template": "portfolio",
  "provider": "cloudflare-pages",
  "projectPath": "./my-site",
  "projectId": "未获取",
  "domain": "未获取",
  "lastBuild": { "at": "2026-09-21T00:00:00Z", "result": "pass" },
  "lastDeployment": { "id": "未执行", "url": "未执行", "at": "未执行" },
  "authorization": { "scope": "本地构建和指定项目部署", "grantedAt": "未获取", "evidence": "对话/官方控制台" },
  "next": "等待用户确认精确域名和生产发布",
  "evidence": ["本地命令输出路径或官方部署 URL"]
}
```

不要写 token、cookie、密码、验证码、银行卡、私钥、身份证信息或完整私人联系资料。`projectPath` 用相对路径提示，不把机器绝对路径写进公共仓库。

## 验收矩阵

| 门 | 最小检查 | 证据 |
| --- | --- | --- |
| 内容 | 用户确认身份、作品、联系方式和示例替换 | 对话确认或内容清单 |
| 本地 | `build`、生产 `check`、四模板 smoke test | 命令输出、`dist` 文件清单 |
| 平台 | 部署 ID、平台 URL、构建日志无错误 | 官方 CLI/控制台链接 |
| 域名 | DNS、HTTPS、根域和 www/子域按目标工作 | `dig`、浏览器回读、平台状态 |
| 页面 | 首页、404、robots、sitemap、外链、移动宽度、图片和字体 | 浏览器回读和结果记录 |

技术命令成功只证明命令完成，不等于用户验收、发布合规或公网可用。

## 续接流程

1. 读取状态文件和实际目录，确认模板、内容、配置和最近构建时间。
2. 查询平台远端的项目、部署和域名状态；冲突时以当前可审计远端证据为准，并标记本地记录过期。
3. `DISCOVERY` 补访谈，`CONTENT_READY` 构建，`LOCAL_VERIFIED` 登录/部署，`DEPLOYED` 做域名和公网验收，`DOMAIN_PENDING` 只处理 DNS/TLS。
4. 只问当前阻塞的 1–3 项。登录过期只请求重新登录；域名已存在不要重新购买；已有项目不要无故重建。
5. 完成后写入新证据和下一检查点，不覆盖旧部署 ID。

## 回滚与失败

页面出现 404、资源缺失、错误内容、意外生产文案、TLS 失败或关键外链错误时暂停推广，保留当前 URL/ID，回滚到上一个已验收版本。回滚后重新做平台和公网验收；代码回滚不自动恢复数据库或表单数据。

- `WAITING_USER`：缺少回答、登录接管、支付或明确发布确认。
- `BLOCKED`：平台限制、域名不可用、权限不足或外部故障，需要改变方案或等待。
- `FAILED`：本地脚本或部署命令可重复修复的错误，保留输出并修复后重试。
- `VERIFIED`：内容、本地、平台、域名和页面必要证据均具备。
